Destacado Microservicios · Full Stack

NutriPlan

Una app para organizar la alimentación de la semana con el objetivo de bajar de peso. Calcula tus calorías según tu perfil (metabolismo basal, actividad y déficit), arma el plan automáticamente con recetas saludables y genera la lista de compras con el costo estimado en supermercados argentinos.

Ver código

Cómo funciona

  • El usuario inicia sesión con Keycloak a través de un gateway BFF (OAuth2 + PKCE): el navegador nunca ve los tokens.
  • recipe-service gestiona 133 recetas con búsqueda clásica y semántica con embeddings (“algo liviano para la cena”).
  • planner-service genera el plan priorizando proteína y variedad, calcula macros, adherencia y la lista de compras agrupada por góndola.
  • pricing-service consulta precios todos los lunes y puede desplegarse como AWS Lambda; los servicios se comunican por eventos en Kafka.

Desafío técnico: mantener los datos consistentes entre microservicios sin transacciones distribuidas. Lo resolví con Transactional Outbox, consumidores idempotentes y dead-letter topics.

Tecnologías y por qué

Java 21 + Spring Boot 4
Para microservicios es el ecosistema más completo: seguridad OAuth2, JPA, Kafka, caché y resiliencia vienen integrados y probados. Frente a Node o Python, el tipado fuerte y las transacciones de Spring dan más seguridad en un dominio con muchas reglas (calorías, macros, porciones). Además es el stack que más piden las empresas.
Angular 22 + TypeScript
Trae todo resuelto (rutas, formularios, HTTP, inyección de dependencias) sin sumar librerías sueltas como pasa con React. Su estructura de servicios e inyección se parece a Spring, así que el código front y back sigue las mismas ideas.
Keycloak (OAuth2 / OIDC)
Login, roles y SSO estándar sin programar la autenticación a mano: más seguro que un login propio y gratis frente a Auth0.
Kafka
Los servicios se avisan cambios con eventos durables y reprocesables. Si uno se cae no se pierde nada, cosa que con llamadas REST encadenadas no pasa.
Redis · MySQL
Redis guarda sesiones y caché en memoria (respuestas rápidas). MySQL, una base por servicio, porque recetas, ingredientes y planes son datos claramente relacionales.
Ollama · Docker Compose
Embeddings locales sin pagar una API externa, y todo el entorno se levanta con un solo comando.

Dashboard · Full Stack

iRacing Dashboard

En el simulador iRacing cada auto y pista se compra por separado y cada serie exige contenido distinto. Este dashboard reúne garage, pistas, series e historial de carreras en un solo lugar y responde una pregunta concreta: ¿qué conviene comprar para correr más series con menos plata?

Ver código

Cómo funciona

  • Se conecta a la API oficial de iRacing o funciona offline con datos mock, así cualquiera puede probarlo sin cuenta.
  • El análisis de overlap cruza las series elegidas con el calendario de la temporada y ordena las pistas según cuántas carreras habilitan.
  • El Shop Advisor arma una lista de compra y muestra el gasto acumulado por categoría.

Desafío técnico: ignorar las semanas que ya pasaron en la temporada para que las recomendaciones solo incluyan compras que todavía se pueden aprovechar.

Tecnologías y por qué

Python 3.11 + FastAPI
El trabajo pesado es consumir la API de iRacing y cruzar datos (series × pistas × semanas), y Python lo hace con muy poco código. FastAPI agrega validación automática y documentación OpenAPI; para una herramienta personal, Spring hubiera sido más estructura de la necesaria.
SQLite
Un solo usuario y sin servidor de base que mantener: el archivo viaja con el proyecto y alcanza.
React 18 + TypeScript + Vite
Para un dashboard con muchos componentes chicos y reutilizables (tarjetas, filtros, gráficos), React es liviano y flexible. TypeScript evita errores al manejar las respuestas de la API y Vite recarga al instante.
Tailwind CSS + shadcn/ui
Componentes accesibles y consistentes sin escribir CSS desde cero, con control total del diseño.

API REST · Backend

Operación Fuego de Quasar

Una API que ubica una nave a partir de lo que reciben tres satélites: la distancia de cada uno a la nave y un mensaje que llega a cada satélite con partes incompletas. Con esos datos calcula la posición y reconstruye el mensaje original.

Ver código

Cómo funciona

  • Calcula la posición por trilateración: la nave está donde se cruzan las tres distancias.
  • Reconstruye el mensaje combinando los fragmentos de cada satélite y corrigiendo el desfasaje entre ellos.
  • POST /topsecret recibe los tres satélites juntos; /topsecret_split permite enviarlos de a uno y consultar cuando estén todos.

Desafío técnico: separar la lógica en servicios independientes (posición y mensaje) detrás de interfaces, para poder testear cada cálculo por separado.

Tecnologías y por qué

Java
Los cálculos de trilateración trabajan con decimales y coordenadas: el tipado estático y los tipos numéricos precisos de Java evitan los errores silenciosos que aparecen en lenguajes dinámicos. Además es el lenguaje del puesto al que apuntaba el desafío.
Spring Boot
Exponer los endpoints REST, validar el JSON y separar controller y services con inyección de dependencias sale casi sin configuración, y la lógica queda aislada para testearla.
Maven
Build reproducible con el wrapper (mvnw): cualquiera lo compila sin instalar nada aparte.

Clean Architecture · Full Stack

Concursos Escolares

Los concursos departamentales de escuelas se publican en distintos sitios y es fácil perderse uno. Este sistema los recolecta automáticamente, los centraliza en un solo lugar y avisa cuando aparece uno nuevo.

Ver código

Cómo funciona

  • Un scraper por sitio detrás de una interfaz común: páginas estáticas con Cheerio y páginas dinámicas con un navegador headless.
  • Un scheduler recorre las fuentes periódicamente, descarta lo ya visto y registra cada ejecución.
  • Los concursos se guardan en MySQL con migraciones versionadas y se consultan desde un frontend en React.

Desafío técnico: que agregar un sitio nuevo sea escribir un scraper y nada más. Por eso el dominio no depende de ninguna fuente concreta (principios SOLID).

Tecnologías y por qué

Node.js + TypeScript
El scraping consiste en esperar muchas respuestas de red, y el modelo asincrónico de Node lo resuelve con poco consumo. Las mejores herramientas para controlar navegadores (Playwright, Puppeteer) nacieron en este ecosistema. TypeScript da el tipado que le faltaría a JavaScript solo.
Fastify + Zod
API rápida y liviana, con validación de datos de entrada tipada de punta a punta.
Playwright · Cheerio · node-cron
Cheerio para HTML estático (rápido), Playwright cuando el sitio arma la página con JavaScript, y node-cron para correr todo de forma programada sin infraestructura extra.
Prisma + MySQL
Esquema tipado y migraciones versionadas: los cambios en la base quedan en el repo y TypeScript avisa si el código no coincide con las tablas.
React + Vite
Interfaz simple de listados y filtros, con un mismo lenguaje (TypeScript) en front y back.
